# iOS native artwork and wallpaper

This target uses SwiftUI and MetalKit, with Spine 3.8 evaluated by a small Objective-C++ bridge. No Node server or WebView runs inside the app. The current simulator development baseline is Xcode/iOS 27.2, iPhone 17 Pro; deployment target is iOS 27.0. iOS 27.3 has not been tested.

## Prepare a small offline pack

Install the repository's Node dependencies. Configure the existing resource scanner with ignored local configuration. Create an ignored `config/ios-samples.local.json` containing explicit `modelIds` and `backgroundIds` arrays from the local catalog. Optional `maxBytes` defaults to 80 MiB. Select a few illustrations, not whole resource directories. The development pack uses two dynamic illustrations, two static illustrations and two backgrounds.

Run from the project root:

```sh
npm run ios:prepare
npm run ios:build
```

Preparation normalizes textures using the desktop pipeline, exports only the whitelist, and fetches the pinned Spine runtime. It preserves an existing pack if export or dependency preparation fails. Generated files stay under ignored `build/ios/`; no game artwork is checked in. On a fresh Xcode installation, accept the license in Xcode, install an iOS simulator runtime, and install the Metal Toolchain component when Xcode requests it.

Open `ios/ArkArtwork.xcodeproj` and choose the ArkArtwork scheme and an iPhone 17 Pro simulator. The project is generated by `scripts/generate-ios-project.mjs`; make build-setting changes there. `npm run ios:build` regenerates it automatically. The built app is under `build/ios/DerivedData/Build/Products/Debug-iphonesimulator/ArkArtwork.app`.

For CLI installation and tests, replace DEVICE_UDID with an available simulator ID from `xcrun simctl list devices available`:

```sh
xcrun simctl install DEVICE_UDID build/ios/DerivedData/Build/Products/Debug-iphonesimulator/ArkArtwork.app
xcrun simctl launch DEVICE_UDID org.arkwallpaper.ArkArtwork
xcrun simctl privacy DEVICE_UDID grant photos-add org.arkwallpaper.ArkArtwork
xcodebuild test -project ios/ArkArtwork.xcodeproj -scheme ArkArtwork \
  -destination 'platform=iOS Simulator,id=DEVICE_UDID' \
  -derivedDataPath build/ios/DerivedData ARCHS=arm64
npm test
```

The UI smoke test saves one generated Live Photo to the selected simulator's Photos library. It does not modify the host Mac photo library. Unit tests exercise metadata pairing, timed cover marker, frame motion, PhotoKit decoding, cancellation cleanup and static export. Runtime scene tests use the generated sample pack; Node exporter tests use synthetic fixtures.

## Use the app

Choose an illustration, optionally search/filter by static or dynamic type, choose a background image or color, drag and pinch to compose. Reset restores the default framing. Pause affects the preview; export starts the model's idle animation in an independent scene. Tap dynamic artwork for supported interaction animations.

In portrait, tap the wallpaper control. Dynamic models export a 3-second, 30 fps, silent Live Photo; static models export a JPEG. Output is 1080 pixels wide with the viewport's aspect ratio. The photo/video includes the chosen background and framing, without app controls. Preview it and tap Save to Photos. Only add-only Photos permission is requested. If denied, grant permission in system Settings and retry. Cancel or leave the app during rendering to stop export; temporary files are removed when the sheet closes.

To set the wallpaper, use iOS Settings > Wallpaper > Add New Wallpaper > Photos > Live Photo, choose the saved artwork and enable playback. The app does not directly change system wallpaper. iOS decides whether a particular Live Photo supports lock-screen motion. A successful PhotoKit import/playback is not proof of lock-screen eligibility. Home-screen wallpaper remains static; continuous home-screen animation is not a supported capability of this app.

## Resource contract and failure behavior

`ios/Resources/pack.schema.json` describes version 1. Each selected model names its image or Spine atlas, skeleton and all texture pages; each page records straight/PMA alpha. Backgrounds contain one or two images. Every dependency is listed with size and SHA-256. Unsafe relative paths and malformed manifests are rejected. File content is validated when a model/background is loaded, so one missing file does not hide all other models.

`HTTPResourceProvider` implements per-character downloads, full downloads, cached updates, cancellation and offline reuse. Open the download icon to configure the HTTPS service and manage resources. Release builds include a generated default endpoint; source keeps only a generic configuration example. See `docs/resource-updates.md` for the shared protocol. Payload paths, sizes and SHA-256 hashes are validated before installation.

## Distribution

The generated project disables signing for simulator development. Real-device deployment requires configuring signing with the developer's own team and reviewing third-party licensing. Game artwork, resource packs, local configuration, reports, screenshots, downloaded runtimes and builds are excluded from Git. Do not publish these sample assets with source code.

## Validation record (2026-11-12)

- Prepared pack: 4 illustrations (2 dynamic, 2 static), 2 backgrounds, 19,077,392 resource bytes (18.2 MiB), plus manifest/license. The separated-alpha static sample was visually checked as a complete illustration.
- `npm test`: 44 passed. Xcode test run: 11 native tests and 1 end-to-end UI test passed, zero failures/skips. The UI test verified all four samples, backgrounds, gestures/reset, pause, portrait/landscape, static export, Live Photo preview and Photos save.
- Native texture tests reproduce the low-alpha PMA rounding regression and verify exact GPU upload bytes after correction. PMA pages use bounded direct decoding of normalized RGBA8 PNG; straight-alpha images use ImageIO/CoreGraphics. All five PNG row filters and truncated inputs are covered.
- Simulator screenshots and sampled exported video frames were visually inspected. The saved clip has visible motion, the selected background and no app controls. The exact test report and captures stay under ignored `build/ios/review/FinalWallpaperTests.xcresult` and `build/ios/review/final-attachments/`.
- The iOS 27.2 simulator Settings list has no Wallpaper entry. System lock-screen configuration/wake playback could not be verified here. A physical-device check of the generated Live Photo is still required; this report does not claim lock-screen motion eligibility, physical-device performance, signing or iOS 27.3 compatibility.
- Independent review found a PMA precision issue, fixed with a RED-to-GREEN native pixel regression. Deferred minor: preparation retains `SamplePack.previous-*` backups, so repeated preparation uses additional local build storage.

## v0.2.0 distribution

The public release includes an Apple Silicon iOS Simulator app with the small sample pack and resource downloads. It is not a signed device IPA. Install the extracted `.app` with `xcrun simctl install booted ArkArtwork.app`; run `xcrun simctl launch booted org.arkwallpaper.ArkArtwork`. Real-device distribution requires an Apple signing identity and provisioning profile, neither of which is included.
